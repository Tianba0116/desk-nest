## ✨ 愿景

很多桌宠只会卖萌，很多助手又只会回答问题。DeskNest 想把两者合在一起，让它们围绕**同一件事**形成完整的流程：

```text
你分享一件事 → 它当下给出合适的回应 → 需要时帮你记下或执行
            → 经你同意或约好后来跟进 → 你更新进展
            → 下次还能接上；值得纪念时由你决定保存
```

**规划中的能力**（全部在计划中，见[路线图](#️-路线图)）：

| | 能力 | 说明 |
| --- | --- | --- |
| 🐾 | **安静相处** | 透明窗口，不挡点击，不抢焦点，全屏时自动避开 |
| 🏠 | **小窝** | 统一面板：小本子（随手记、待办）、沙漏（专注）、信箱、相册、小箱子、相处设置 |
| ⏰ | **提醒** | 到点进入信箱并弹出气泡；可改期、可取消 |
| 💬 | **对话** | 接入你自己配置的模型；没配置或断网时，本地功能照常可用 |
| 🛠️ | **一句话操作** | “明天下午三点提醒我改简历”→ 生成一条真实的提醒，并给你看结果卡片 |
| 🧠 | **记得近况** | 记住你在忙的事和进展；你可以查看、更正和删除，被纠正的旧说法不会再出现（见下方[记忆系统](#-亮点设计记忆系统)） |
| 🔔 | **约定跟进** | 到了约好的时间，主动来问一句“那件事怎么样了” |
| 📰 | **资讯与文章** | 按订阅源生成每日摘要，总结你提交的文章；每条都附原文链接 |

### 🧠 亮点设计：记忆系统

> [!TIP]
> 这是后续重点打磨的设计，目前**还没有实现**（计划在 M7 首次落地）。下面是设计思路，细节见 [技术方案 §9](docs/02-technical-design.md#9-记忆事项与上下文构建)。

很多 AI 伙伴的记忆是“把聊天记录都塞进去，让模型自己看着办”，结果常常是记错了改不掉、忘不掉，或者硬凑出不相干的“我记得”。DeskNest 的记忆想做到：**记得准、改得掉、忘得干净，而且每一条都说得出来源。**

**1. 分层存储，不把所有东西都叫“记忆”**

```text
            ┌───────────── 进入对话上下文的优先顺序 ─────────────┐
  高 ──▶   显式偏好   称呼、表达风格、安静时段……（你直接设置的）
           事项/待办  你正在忙的事和最新进展（直接读业务记录，不另存副本）
           记忆       短期事实（带有效期）、你确认过的信息
           共同回忆   你决定保存下来的纪念内容
  低 ──▶   聊天历史   只带最近几轮；历史存在 ≠ 都可以当作事实
```

**2. 显式才记**：“叫我小林”“记住我在准备面试”会直接生效；平时随口聊的内容不会被偷偷记成事实。模型推测出来的内容，只能先成为“待确认”，你点头才生效。

**3. 有来源、有期限**：每条记忆都能查到来自哪次对话或哪次操作。“今天好累”这类临时信息会过期，过期后不再提起。

**4. 纠正和忘记贯穿全链路**：只改一条记录是不够的，旧说法还会藏在聊天历史、摘要、缓存里。所以纠正或忘记时会：

- 递增上下文版本号（contextEpoch），正在生成的旧回复立即作废，用新上下文重来；
- 截断纠正点之前的聊天历史，只让结构化的新事实进入上下文；
- 清理相关的检索缓存、待确认候选和排队中的主动消息；
- 区分“不再用于记忆”和“删除本机记录”，让你自己选择清理到什么程度。

**5. 记不起就承认**：检索没有明显命中时，宁可问一句或承认没找到，也不为了显得“记得”而拿不相关的内容凑数。

## 🚀 快速开始

**环境要求**：Node.js（开发机用的是 24.20）；运行和打包需要 Windows 10/11 x64。

```bash
npm install          # 安装依赖
npm run dev          # 开发模式（渲染层支持热更新）
npm run typecheck    # 类型检查
npm test             # 单元测试（Vitest）
npm run package      # 打包到 release/<版本>/（解压版 + zip）
```

<details>
<summary><b>常见问题</b></summary>

- **Electron 二进制没有下载成功**：运行 `node node_modules/electron/install.js`。需要代理时，先设置 `HTTPS_PROXY`。
- **想调试宠物窗口**：先设置环境变量 `PET_DEVTOOLS=1`，再运行 `npm run dev`。
- **宠物找不到了**：右键托盘图标，选“找回宠物”，它会回到主屏中央。

</details>

## 🧭 设计原则

这几条贯穿整个项目，以后每个功能都要遵守：

- **结果说了算，模型的话不算**：操作是否成功，以本地事务和命令收据为准。失败、缺信息、还在等待，都不能显示成“已完成”。
- **离线也好用**：没配置模型或断网时，本地交互、表单工具、提醒和已有数据都能正常使用。
- **数据在你手里**：数据只存在本机，不建账号，不做云同步；你能查看、更正和删除保存的信息。
- **不打扰**：透明区域不挡你工作，不抢焦点；主动互动有依据、可以控制，忽略它也没有惩罚。
- **一个入口**：界面和模型走同一个命令入口；写操作带 operationId，可以安全地重试。
- **边界清楚**：渲染进程不直接碰数据库、文件系统、密钥和模型服务；网页、文章等外部内容一律当作不可信数据处理。

## 🧱 技术栈与项目结构

**Electron** · **React** · **TypeScript**（严格模式）· **Vite**（electron-vite）· **Zod** · **Vitest** · **electron-builder**

```text
desk-nest/
├── src/
│   ├── main/              # 主进程
│   │   ├── index.ts       #   入口：单实例、托盘、生命周期
│   │   └── desktop/       #   宠物窗口、拖动、位置保存、托盘
│   ├── preload/           # 预加载脚本：向渲染层暴露受限的 IPC
│   ├── renderer/          # 渲染层（React）
│   │   └── pet/           #   宠物角色、动画、拖动手势
│   └── shared/contracts/  # 主进程与渲染层共用的 IPC 契约（Zod）
├── tests/unit/            # 单元测试
└── docs/                  # 需求、方案、决策、路线图、实机验证记录
```
