# 里程碑路线图

- 版本：v0.4（2026-11-27，展开 M8）
- 对应需求：01-requirements.md v0.4；对应方案：02-technical-design.md v0.4

需求 §8 的 P0/P1/P2 说明“最终要交付什么”，这份路线图说明“按什么顺序一版一版做”。每个里程碑必须满足三点：

1. 是一个可以运行、可以试用的版本，不是半成品分支；
2. 只做本里程碑列出的内容，后面里程碑的功能不提前做；
3. 完成后在 `docs/verification/Mx.md` 留下 Windows 实机验证记录，未测试的项目写“未验证”。

P0 的技术验证项不集中在开头做，而是放在第一次需要它的里程碑里完成，验证结论回写 03-decisions.md。

## M1 能拖动的宠物

**目标**：在 Windows 桌面上出现一个能拖动的占位角色，并验证透明窗口最基础的几项假设。这一版的结果决定后续是否继续使用 Electron（D-01）。

**范围**

- 工程：Electron + React + TypeScript + Vite；dev、typecheck、test、build、package 命令。
- 宠物窗口：透明、无边框、不在任务栏显示、尺寸贴合角色、不获取键盘焦点。
- 占位角色：待机（呼吸）、眨眼、被拎起、落地，以及很短的触碰晃动，用来区分触碰和拖动。
- 拖动：按下后移动超过 5 DIP 才开始拖动；松开、指针被系统取消、窗口隐藏、锁屏、睡眠都会结束拖动。
- 穿透：角色以外的透明区域不挡下层窗口的点击。
- 托盘：显示/隐藏、找回宠物（移到主屏中央）、版本号、退出。
- 单实例：再次启动时唤出已有的宠物。
- 位置：按显示器和相对位置保存，重启后恢复；显示器移除后移入现存屏幕。存为 JSON 文件，M3 再迁入 SQLite。
- 产出：Windows 解压版和 zip，以及 `docs/verification/M1.md` 实机记录。

**本里程碑不做**：对话、数据库、提醒、小窝面板、右键菜单、边缘吸附、全屏隐藏、尺寸调节、正式美术。

**已知限制**：M1 使用普通置顶层级，外部应用全屏时宠物可能压在上面，M2 解决（R02.AC-8、D-04）。

**完成条件**：`docs/verification/M1.md` 中的必测项都在实机上通过；未通过的项目有记录，并写明处理方式（按 TD §12.2 的失败处理顺序）。

## M2 有反应的宠物

**目标**：宠物对拖动、触碰和右键有完整反馈；外部应用全屏时不挡画面；用户能调整尺寸和动态效果。验证外部全屏识别和置顶层级（D-04）。

**范围**

- 落地与吸附：拖动松手后播放落地动作；窗口靠近工作区边缘（约 24 DIP 内）时贴边（R02.AC-4）。
- 右键菜单：在角色上右键弹出菜单，提供隐藏宠物、找回宠物、尺寸、降低动态效果、全屏时保持显示（R02.AC-5）。对话、小窝、安静模式在对应功能出现的里程碑加入菜单（M3 小窝、M4 安静模式、M5 对话），不放无效入口。
- 外部全屏：定义 `DesktopContextProvider`，Windows 实现读取前台窗口与所在显示器，输出 `fullscreen: true | false | 'unknown'`。全屏窗口与宠物在同一显示器时自动隐藏宠物，退出全屏后恢复；结果未知时保持显示，不提升置顶层级；系统隐藏不改变用户的“隐藏宠物”状态（R02.AC-8、TD §12.4）。
- 尺寸：小、中、大三档，按底部中点保持位置，重启后保持（R04.AC-3）。
- 降低动态效果：应用内开关，与系统“动画效果：关”任一开启即生效；循环动画停止，一次性动作改为短淡入（R04.AC-4）。
- 设置持久化：继续使用 userData 下的 JSON 文件（与位置文件相同的写入方式），M3 迁入 SQLite。
- 托盘菜单同步提供尺寸、降低动态效果、全屏时保持显示，宠物窗口的全部功能都能从托盘完成（R21.AC-4）。
- 产出：Windows 解压版和 zip，`docs/verification/M2.md` 实机记录；D-04 写入实测结论。

**本里程碑不做**：对话、小窝、安静模式、数据库、吸附滑动动画（P2 完善）、正式美术、文字拖入。

**依赖**：全屏识别使用 koffi（FFI，自带各平台预编译文件，无需本地编译）调用 user32；加载或调用失败时结果记为 unknown，不影响其他功能。

**完成条件**：`docs/verification/M2.md` 必测项在实机上通过或有记录；D-04 写明各类全屏的实测识别结果。

## M3 小窝与本地数据

**目标**：有一个能真正保存数据的小窝：随手记和待办可以增删改查、可以搜索；数据写入走统一命令入口并带收据。完成数据库驱动选择（D-05）。

**范围**

- 数据库：Electron 内置的 `node:sqlite`（D-05），数据文件在 userData；WAL、外键、`user_version` 记录 schema 版本；每次迁移在事务内执行，已有数据库升级前用 `VACUUM INTO` 备份；迁移失败不删库。
- 命令入口：`CommandService` + 命令注册表（名称、输入 schema、执行函数、是否开放给模型）；写操作带 operationId，业务写入与 `command_receipts` 同一事务提交；同 ID 同参数返回原结果，不同参数返回 `IDEMPOTENCY_CONFLICT`；带 revision 的修改检查版本（TD §6）。提交后发失效通知，界面重新查询。
- 随手记（R06）：创建、列表、修改、删除；删除后 10 秒内可撤销，回收站保留 7 天，可恢复或彻底删除（R06.AC-1～2）。
- 待办（R07）：创建、查看、修改、完成/取消完成、记录进展、删除（同样可撤销）；完成状态只由用户操作改变（R07.AC-1～2）。
- 搜索：笔记和待办的规范化子串搜索（全半角、大小写、空白统一），支持 1～2 个字的查询（R06.AC-3）。
- 小窝窗口（R15 基础）：普通可聚焦窗口，包含“笔记”“待办”“回收站”和顶部搜索；关闭只隐藏，不退出（R01.AC-3）；全部操作可用键盘完成。
- 入口：托盘和右键菜单加入“打开小窝”。
- 位置和外观设置从 JSON 文件迁入 `app_settings`（首次启动时导入一次）。
- 产出：Windows 解压版和 zip，`docs/verification/M3.md`。

**本里程碑不做**：对话（含 R06.AC-4 的“对话创建笔记”，M6 做）、提醒、信箱、事项与待办关联（R07.AC-3，M7）、删除待办时取消提醒（R07.AC-4，M4 随提醒一起做）、导出恢复（M8）、聊天记录。

**完成条件**：`npm test` 覆盖命令收据、幂等冲突、版本冲突、事务回滚、搜索和迁移；打包版能创建数据、重启后仍在；`docs/verification/M3.md` 有记录；D-05 写明证据。

## M4 提醒

**目标**：用表单创建一次性提醒；到期后进入信箱并在宠物旁弹出气泡；可以改期、推迟、取消。重启和睡眠后提醒仍然有效。

**范围**

- 数据：`scheduled_actions`（本里程碑只有 kind=reminder）、`inbox_items`（含 `shown_at`）；提醒可关联一个待办（R08、TD §8.2）。
- 命令：创建、改期、推迟、取消提醒；信箱标为已读、全部已读。时间已经过去时拒绝创建并提示，不静默创建立即到期的提醒（R08.AC-4）。删除待办时同一事务取消关联提醒（R07.AC-4）。
- 调度：最近到期定时器 + 20 秒兜底扫描；启动、睡眠恢复、解锁时主动扫描；到期处理在短事务内重新读取状态、唯一键防止重复入箱（TD §8.3）。
- 展示：到期提醒在宠物旁的气泡中显示，多个合并为一个气泡；关闭气泡不等于已读（R15.AC-3）；界面确认显示后写 `shown_at`。应用未运行期间错过的提醒，24 小时内的汇总提示一次，更早的只进信箱（R08.AC-6）。宠物显示未读标记。
- 安静模式：托盘和右键菜单切换；安静、宠物隐藏或外部全屏时提醒只进信箱，是否另发系统通知由独立设置控制，默认关闭（R08.AC-8、D-13 暂定）。
- 小窝新增“提醒”和“信箱”：表单创建（内容、日期时刻、可选关联待办），成功卡片显示完整本地日期、星期和时刻并可立即修改（R08.AC-2）；已取消/已改期的历史卡片只显示状态，没有操作按钮（R15.AC-4）。
- 运行条件（R01.AC-3～6、R08.AC-9）：开机启动默认关闭，托盘可切换（仅打包版）；首次创建提醒时提示一次并提供开启入口和“不再提示”；成功卡片在未开启时注明“应用运行时会准时提醒”；有未来提醒时“退出”会先确认。
- D-03：本里程碑按“不可行”分支实现（不注册系统计划通知），P0 验证后再决定是否补充。
- 产出：Windows 解压版和 zip，`docs/verification/M4.md`。

**本里程碑不做**：对话创建提醒和中文时间理解（M6）、重复提醒（首版不支持；表单没有重复选项）、跟进（M7）、系统计划通知、完整投递状态机（P2）。

**完成条件**：单元测试覆盖到期入箱、重复扫描不重复入箱、改期/取消后旧时间不再提示、错过提醒的汇总规则、删除待办取消提醒；`docs/verification/M4.md` 有记录。

## M5 对话

**目标**：配置模型后可以和宠物聊天；单击宠物打开对话。未配置模型或断网时如实提示，本地功能不受影响。确定首个模型协议（D-02）和本阶段的流式方案（D-06）。

**范围**

- 模型扩展点：`ModelAdapter`（事件流 + 能力声明）+ 适配器注册表 + 配置 schema（TD §7.1、§14.1）。首个适配器为 **OpenAI 兼容协议**，预设 DeepSeek、通义千问、Kimi、智谱、本地 Ollama 和自定义地址；其他协议以新适配器加入，不改对话流程（D-02）。网络请求走 Electron `net.fetch`，跟随系统代理。
- 模型设置（R18）：小窝“设置”页填写服务地址、模型名、密钥，并可“测试连接”；密钥用系统加密（safeStorage）保存在主进程，界面不回显、不写日志；系统加密不可用时只在本次运行期间保存在内存并明确提示；首次配置云服务时说明对话内容会发送到该服务，并需要确认。
- 对话窗口：单击宠物（未拖动）打开或收起宠物旁的对话窗口；右键菜单和托盘也有“对话”。窗口只在用户打开时获得焦点（R02.AC-6）。
- 对话（R05）：流式显示回复；随时停止，停止后保留已显示的部分并标为“已停止”；状态区分“正在想”“回复中”“已完成”“已停止”“失败”；失败可重试，重试不会重复保存用户消息；只携带最近 12 条有效消息；同一时间只有一轮进行中。
- 持久化：`turns`、`messages` 表；发送消息是带 operationId 的命令（用户消息与 turn 同一事务提交），网络请求在事务外。重启时未完成的轮次标为“已中断”，不自动重发。
- 离线（R18.AC-4～6）：未配置模型时提示去设置，输入保留在输入框；网络失败时用户消息标为“未发送”，恢复后由用户点“重试”，不自动发送。系统提示词说明本阶段不能替用户创建提醒、笔记或待办，避免模型声称已完成操作（R05.AC-5）。
- 流式方案（D-06）：本阶段没有工具调用，采用单次直接流式；两段式与“流式 + 撤回”的比较在 M6 引入工具时进行。
- 产出：Windows 解压版和 zip，`docs/verification/M5.md`。

**本里程碑不做**：工具调用与自然语言操作（M6）、称呼偏好（M6）、记忆与上下文纠正（M7）、聊天记录保留期与按条删除（M8，D-08）、多会话。

**完成条件**：单元测试覆盖 SSE 解析、错误分类、停止、失败重试不重复、重启中断、上下文条数、未配置/断网路径；配置真实服务后在实机完成一次流式对话并记录服务和模型名（需要用户提供密钥）。

## M6 用一句话操作

**目标**：在对话里说“明天下午三点提醒我改简历”，得到一条真实保存的提醒和本地结果卡片；缺信息时先问，不声称成功；模型重试、停止、重启都不会产生重复或丢失的操作（P1-A 退出条件）。在所选服务上实测工具调用（D-02），比较两种流式方案并关闭 D-06。

**范围**

- 开放给模型的工具（`exposeToModel: true`，其余命令保持关闭）：
  - `reminders.create`：创建一次性提醒（R08 对话路径）。
  - `notes.create`：创建随手记（R06.AC-4，M3 延后到这里）。
  - `preferences.setNickname`：设置称呼（R10.AC-2）。
  - 工具定义由命令注册表生成（名称、说明、参数 schema），不单独手写一份；模型只看到工具参数，operationId、来源、时区由本地填写。
- 时间理解（TD §8.1）：
  - 模型只填时间语义结构（相对日、日期、上午/下午、时、分、`recurrence`，并保留原文片段），不填时间戳。
  - 本地 `TimeResolver` 以本轮消息的接收时间和系统时区算出绝对时间。
  - 本地规则层再检查原文：识别到“每天/每周/工作日/每隔”等重复表达时，即使模型漏填 `recurrence` 也不会静默只建一次。
- 缺信息与异常时间（R08.AC-3、AC-4、AC-7）：
  - 只说“下午”、没有内容、目标不明确时，生成待补充草稿（`turn_actions.state = awaiting_input`），只问缺的那一项；用户下一句补上后补入原草稿，重新校验后才执行。
  - 草稿 30 分钟内有效，用户转去聊别的或开始新的操作时作废。
  - 时间已经过去：不创建，给出可选的下一次时间请用户确认。
  - 重复表达：说明暂不支持重复提醒，提供“只设置下一次”；确认后创建，卡片标注“仅一次”。
- 执行与账本（TD §6.3、§7.2、§7.4）：
  - runner 为每个工具调用分配 operationId，先写 `turn_actions`，再走 `CommandService` 执行；业务写入与收据同一事务提交。
  - 每轮上限：3 次模型请求、4 个写操作、1 次参数修复；超过时停在可见的待处理状态。
  - 停止生成不撤销已提交的操作，界面如实列出已完成和已取消的部分。
  - 失败重试：已提交的操作取回原结果，不再执行。
  - 重启时，未完成的轮次按账本和收据恢复卡片，不自动重发模型请求，也不执行未确认的新写操作。
  - 同一轮出现参数相同的重复写操作时，复用已执行的结果；下一轮用户明确再要一份时正常创建。
- 结果卡片（R05.AC-5、R08.AC-2）：
  - 由本地模板按命令结果渲染：提醒卡显示完整本地日期、星期、时刻，附“修改”“取消”（走 UI 命令入口）；笔记卡、称呼卡各有对应的打开或修改入口。
  - 模型文字只做补充表达，不作为成功依据。
  - 卡片在历史记录里随状态更新：已改期、已取消的卡片只显示状态。
- 对话状态（R05.AC-3）：增加“执行中”“等待补充信息”“部分完成”；轮次状态机按 TD §7.2 扩展。
- 流式方案（D-06）：
  - 实现两个可切换的轮次策略：A 两段式；B 单次流式 + 撤回。
  - 用评估集在真实服务上测：首字延迟、请求次数与 token、B 的撤回比例、撤回前是否已显示成功声明。
  - 按结果选定默认方案，关闭 D-06，并定稿 NFR-04 的首字延迟和自然语言操作延迟目标。
- 称呼（R10.AC-1～3 的称呼部分）：
  - 新建 `preferences` 表；小窝“设置”页可以直接设置、修改、清除称呼，不依赖模型。
  - 系统提示词带上当前称呼；修改后下一轮立即使用新值。
- 能力降级：
  - 所选服务或模型不支持工具调用时（能力检测或测试连接失败），只提供聊天，并在对话里说明“可以去小窝添加”；系统提示词按实际开放的工具描述能力边界。
  - 未配置模型、断网时，表单路径与 M5 相同。
- 数据：迁移 v4 新建 `preferences`、`turn_actions`；`turns.state` 增加新状态；消息关联工具操作；提醒和笔记记录 `source_message_id`。
- 评估集（需求 §9.4）：
  - 30～50 条固定中文样例，覆盖普通聊天、明确创建、含糊时间、重复表达、多个目标、否定、改口、取消、重复请求、笔记里的恶意指令。
  - 退出条件：零误执行、零重复写入；用模拟适配器在单元测试中回放，并在真实服务上跑一遍，记录服务名和模型名。
- 产出：Windows 解压版和 zip，`docs/verification/M6.md`，D-06 结论，D-02 的工具调用实测记录。

**本里程碑不做**：
- 用对话修改、改期、取消、查询已有提醒、笔记、待办（M6 通过卡片按钮完成这些操作）。
- 用对话创建待办、关联待办。
- 事项、记忆、约定跟进，以及上下文纠正：截断旧称呼所在的历史、递增 contextEpoch（M7）。
- 称呼以外的偏好：表达方式、兴趣、主动程度、安静时段。
- 重复提醒、离线的中文时间解析、复合命令、多会话、聊天记录保留期。

**已知限制**：改称呼后，旧称呼仍留在最近 12 条历史里，模型可能偶尔沿用；系统提示词会明确以当前称呼为准，彻底截断在 M7 随纠正机制完成。

**完成条件**：
- 单元测试覆盖：工具参数校验与修复、TimeResolver（相对日、上午/下午、跨午夜、过去时间、重复表达）、待补充草稿的补全与过期、停止后已提交操作仍在、重试与重启不重复执行、每轮上限、能力降级。
- 评估集达到退出条件。
- 实机完成 U2 场景：“明天下午三点提醒我改简历”出现正确卡片 → 重启后仍在 → 到期提示；“下午提醒我”会询问时刻；“每天提醒我喝水”提供“只设置下一次”。
- `docs/verification/M6.md` 有记录，D-06 已关闭。

## M7 记住近况与约定跟进

**目标**：
- 宠物能记住你明确让它记住的事和进展；到了约好的时间，按最新进展来问你。
- 你纠正或让它忘记的内容，不会再通过任何途径出现在回复里。
- 完成 P1-B 的退出条件：在固定的多轮测试中不混淆“聊天”“保存”“安排”；被纠正或忘记的信息不会从任何来源回流（需求 §8 P1-B、TD §15）。

**范围**

- **事项（Topic，R11.AC-1～3）**：
  - 持续一段时间的事，例如“准备产品经理面试”。有标题、最新进展、状态（进行中 / 已完成 / 已归档）。
  - “记住我在准备产品经理面试”直接创建事项；平常分享（“最近在准备面试”）不创建任何东西。
  - 可以记录进展；宠物回答时用最新进展，没有进展时就问，不编造结果。
  - 待办可以关联到事项（R07.AC-3）。
- **记忆（Memory，R11.AC-1、AC-6）**：
  - 简短的事实，例如“我对花生过敏”。只有明确说“记住……”才保存。
  - 临时信息可以带有效期，例如“记住我这周都在出差”，过期后不再使用。
- **约定跟进（R12）**：
  - 只有你明确约定时才创建，例如“周五晚上八点问问我面试准备得怎么样”。
  - 保存对象（事项或待办）、目的和时间；时间理解沿用 M6 的本地换算。
  - 可以查看、改期、取消；小窝里也能用表单为某个事项或待办创建跟进。
  - 到期时读取对象的最新状态，按最新进展发问（本地模板，不依赖模型）。进入信箱并弹出气泡，点开后在对话里接着聊。
  - 关联的事项或待办被完成、删除、归档时，同一事务里取消尚未到期的跟进，并在信箱留下“已自动取消”；创建时选了“完成后复盘”的跟进不取消（`stop_policy`）。
  - 跟进不占普通主动闲聊的配额（R12.AC-6）。
- **一句话操作新增的工具**（沿用 M6 的账本、草稿、卡片和去重）：
  - 创建事项、记录事项进展、标记事项完成（卡片上可撤销）；
  - 记住一条记忆；
  - 创建约定跟进；
  - 忘记某个事项或记忆（卡片上可撤销）。
  - 模型要指认某个事项时，只能从本轮上下文里列出的事项中选；对不上或有多个可能时先问。
- **上下文构建（TD §9.3）**：
  - 每轮带上：显式偏好、进行中的事项及最新进展、与本轮输入匹配的有效记忆（中文规范化子串和最近更新排序，最多 8 条），以及有限的近期对话。
  - 已忘记、已过期、已删除的记录不进入上下文。没找到时承认没找到，不拿不相关的内容凑数。
- **纠正与忘记（R10.AC-3、R11.AC-5、TD §9.4）**：
  - 改称呼、修改事项或记忆的内容、忘记、删除，都会递增 contextEpoch，并把“历史下限”设为此刻。之后的上下文只带此刻以后的聊天历史，之前的事实只能通过结构化记录进入（解决 M6 的“旧称呼留在历史里”）。
  - 忘记某条具体信息时，把可以识别的来源消息加入排除列表，以后不会再被读到。
  - 纠正时如果有回复正在生成，中断这次请求，按新上下文重来；已经显示的部分如实标为“旧回复”。
- **“不再用于记忆”与“删除本机记录”（R11.AC-7）**：
  - 忘记：记录保留在“已忘记”列表里，不再进入上下文，可以恢复。
  - 删除：本机记录彻底删除。
  - 界面说明：已经发送给模型服务的内容、本机以外的备份不受本机删除控制。
- **来源（R11.AC-4）**：每个事项、记忆、跟进都记录来自哪次对话或哪次表单操作，卡片和小窝里可以看到。
- **小窝（R11.AC-2、R12.AC-3、R15）**：
  - 小本子新增“事项”页：创建、编辑、记录进展、完成、归档、忘记、删除，查看关联的待办和跟进，为事项创建跟进。
  - “设置”新增“已保存的记忆”：查看、编辑、忘记、恢复、删除，显示有效期和来源。
  - 待办表单可以选择关联的事项，也可以为待办创建跟进。
  - 信箱显示跟进到期和“已自动取消”的卡片。
- **偏好（R10.AC-1 的一部分）**：新增“表达方式”（例如简短、活泼、温柔），设置页直接选，对话里说“说话简短一点”也会生效，并出现可修改的卡片。
- **数据**：迁移 v5 新建 `topics`、`memories`、`context_exclusions`；`tasks` 增加 `topic_id`；`scheduled_actions` 增加 `purpose`、`stop_policy`；`app_settings` 保存 contextEpoch 和历史下限。
- **评估集**：新增 20～30 条固定的多轮中文样例。
  - 覆盖：记住与闲聊的区分、进展更新、按最新进展回答、约定跟进的授权（笔记或分享不能自行安排跟进）、纠正、忘记、过期、完成后自动取消。与 M6 的评估集合计覆盖需求 §9.4 的全部类别。
  - 回流检查：纠正或忘记之后的每一次模型请求，都不能包含旧内容（检查实际发出的请求，而不是检查回复）。
- **产出**：Windows 解压版和 zip，`docs/verification/M7.md`。

**本里程碑不做**：
- 模型推测的记忆和候选确认（R11.AC-8，P2）、自动提取、向量检索、派生摘要。
- 主动陪伴（R13）、共同回忆（R16）。
- 兴趣、主动程度、安静时段等其余偏好（随 R13、R14 一起做；D-11）。
- 删除单条聊天记录、聊天记录保留期（M8，D-08）；数据导出与恢复（M8）。
- 重复的跟进或提醒。
- 用对话修改、改期、取消已有的提醒和跟进（用卡片按钮或小窝）。
- 用对话创建待办。
- 跟进到期时由模型生成问候语。

**已知限制**：
- 匹配记忆只用中文子串和最近更新排序，同义说法（例如“面试”和“求职”）可能匹配不到。这时宠物会说没找到，不会乱猜。
- 纠正后会截断较早的聊天历史，接下来几轮对话的连贯性会差一点。

**完成条件**：
- 单元测试覆盖：
  - 事项和记忆的增删改、进展、完成、归档、忘记、恢复、删除、有效期；
  - 跟进的创建、到期按最新状态发问、完成或删除后自动取消并写入信箱、“完成后复盘”不取消；
  - 纠正或忘记后 contextEpoch、历史下限和排除列表生效，进行中的请求被中断重建；
  - 上下文条数与匹配规则；
  - 待办关联事项。
- 评估集（mock 回放）零误执行、零重复写入、零引用已纠正或已忘记的信息。真实服务评估在用户提供密钥后运行，不作为开工的前提。
- 用本地模拟服务在应用里走完 U3、U5：
  - U3：记住面试 → 记录进展 → 约定周五询问 → 更新进展 → 跟进按最新状态发问 → 事项完成后跟进自动取消。
  - U5：改称呼、忘记一条记忆后不再出现。
- `docs/verification/M7.md` 有记录。

## M8 可自用版本

**目标**：补齐每天使用需要的东西，做出一个可以安装、可以放心自用的版本：专注计时、数据导出与恢复、聊天记录的保留和删除、安装包、基础可访问性。完成 P1-C 的退出条件：P1 范围内的功能真实可用，连续自用至少 3 天（需求 §8 P1-C）。

**范围**

- **专注（R09，D-07）**：
  - 小窝新增“沙漏”页：开始（15 / 25 / 45 / 60 分钟或自定义，可选关联待办）、暂停、继续、提前结束、取消；同一时刻最多一个进行中（含暂停）的会话。
  - 按自然经过的时间计时：睡眠、锁屏、应用退出期间继续计时，暂停时不计时；会话只结算一次，重启后不会重复结算。
  - 到期进入信箱并弹出气泡；结束后让用户选择“完成待办 / 记录进展 / 继续”，不会自动完成待办（R09.AC-2）。
  - 在睡眠、锁屏或应用未运行期间到期的，结果记为“已到期”，回来时展示一次并注明（R09.AC-4）。
  - 统计口径（D-07）：本次专注时长以计划时长为上限，到期后经过的时间不计入；期间锁屏和睡眠的时长单独显示。只展示单次结果，不做统计页面。
  - 专注进行中，到期的提醒和跟进只进信箱、不弹气泡，结束后照常（R08.AC-8）。
  - 检测到系统时间被大幅调整时，暂停会话并提示确认剩余时间，不出现负数或重复结算（R09.AC-7）。
  - 托盘和右键菜单增加“开始专注 25 分钟 / 结束专注”。
- **数据导出与恢复（R19.AC-3、AC-4、TD §13.2）**：
  - 设置页“导出全部数据”：生成一个 JSON 文件，包含全部业务数据和设置，不包含密钥。
  - “从导出文件恢复”：校验文件 → 在临时数据库里重建并检查 → 二次确认 → 备份当前数据 → 重启后整体替换；任何一步失败，现有数据保持不变。恢复后，旧提醒按 R08.AC-6 汇总，不会全部重新弹出。
  - “清除所有数据”（R19.AC-8）：二次确认后删除本机数据库、备份和密钥，然后重启为全新状态。
- **数据库打不开时的恢复界面（R19.AC-5）**：迁移失败或文件损坏时不再直接退出，提供“从最近的备份恢复 / 打开数据文件夹 / 退出”，不删库重建。
- **聊天记录（R19.AC-7，D-08）**：
  - 保留期限：永久（默认）/ 90 天 / 30 天，超期的聊天记录每天自动删除。
  - 对话里可以删除单条消息（连同它的回复）；设置页可以删除最近 1 小时、今天或全部聊天记录。
  - 删除后不再进入上下文；相关的动作账本参数一并清理，卡片仍按记录的当前状态显示，来源显示“消息已删除”。
- **安装包（R20.AC-1、R19.AC-6，D-09）**：
  - 新增 Windows 安装版（NSIS），保留解压版和 zip。覆盖安装保留全部数据。
  - 卸载时默认保留数据，卸载程序询问“同时删除我的数据”并显示数据位置（D-09）。
- **可访问性基础（R21.AC-1～3、AC-6）**：
  - 小窝和对话窗口的全部功能可以只用键盘完成，焦点可见；按钮、卡片、状态都有读屏名称。
  - 正文文字对比度不低于 4.5:1（用脚本检查全部颜色组合）。
  - 150% 缩放下文字不截断、不重叠（用开发工具模拟缩放截图检查）。
  - 应用没有声音，R21.AC-5 的“关闭声音”暂无对象。
- **发布质量（R20.AC-3、AC-5）**：`docs/release-notes.md` 列出已完成和尚未完成的需求、已知限制；`docs/licenses.md` 列出依赖的来源和许可。
- **产出**：Windows 安装版、解压版和 zip，`docs/verification/M8.md`；D-07、D-08、D-09 写入采用的方案。

**本里程碑不做**：
- 专注统计页面（D-07 待确认是否需要）、用对话开始专注、专注时的宠物动画（P2 原创角色时做）。
- 多来源合并的恢复（只支持整体替换）、云同步、自动定期导出。
- 安装包签名和分发渠道（D-12，1.0 前）、自动更新。
- 主动陪伴、共同回忆、原创美术、文字拖入等 P2 内容。

**完成条件**：
- 单元测试覆盖：专注的开始、暂停、继续、结束、取消、唯一进行中、到期结算只一次、离线期间到期、时间跳变、不自动完成待办；导出内容不含密钥、恢复的校验和失败保护、替换流程；聊天记录的保留期、单条和按时间删除、删除后不进入上下文。
- 用本地模拟服务在打包后的应用里走完：专注一轮（到期 → 选择记录进展）、导出 → 清除所有数据 → 恢复、删除聊天记录。
- 安装版在开发机上完成安装、启动、覆盖安装、卸载（保留数据和删除数据各一次）。
- 对比度检查和 150% 缩放检查有记录。
- **你在目标 Windows 机器上连续自用至少 3 天**，记录无响应、错误提醒、窗口干扰和记忆错误；之后根据实际情况重排 M9 起的顺序。

## M2～M8 的展开方式

每个里程碑开工前，先在这里把它展开成与 M1 相同的格式（目标、范围、本里程碑不做、完成条件），再开始写代码。
