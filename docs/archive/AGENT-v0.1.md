## 1. 产品目标与实现原则

构建一个可以在桌面自由拖动、有稳定性格、能记住用户偏好、主动跟进事情并完成轻量工具任务的陪伴宠物。

核心体验：

```text
用户分享事情 → 宠物理解并接住 → 创建记录或任务
             → 在合适时机跟进 → 一起完成 → 留下可查看的记忆
```

第一版必须同时具备以下能力：

- 身体互动：透明桌面、拖动、落地、摸头、待机和情绪动作。
- 基础陪伴：简短对话、稳定性格、安静相处、适度主动互动。
- 工具：随手记、提醒与待办、专注陪伴。
- 个性化：称呼、表达偏好、主动程度、安静时段和兴趣。
- 连续记忆：正在进行的事情、可纠正的偏好、经用户确认的共同回忆。
- 小窝：统一访问工具、信箱、记忆、回忆和外观设置。

实现原则：

1. 工具结果必须来自真实执行结果；模型生成的文字不能作为执行成功的依据。
2. 宠物可以选择保持安静。自主性由事件、规则和决策共同实现，不依赖定时随机发话。
3. 用户明确指令优先于推测。一次忽略不能直接成为永久偏好。
4. 动作表达状态，卡片展示事实，记忆延续关系。
5. 情绪状态用于角色表现，不将其描述为真实意识，也不以忽略、离线或未喂食惩罚用户。
6. 未配置模型或模型不可用时，桌宠、工具、显式偏好、提醒和已有数据仍然可用。
7. 数据与角色素材解耦；更换皮肤不应丢失用户记忆与任务。

## 3. 建议技术栈

| 层 | 选型 | 目的 |
| --- | --- | --- |
| 桌面容器 | Electron，实施时选择受支持稳定版并锁定版本 | 透明窗口、托盘、全局快捷键、多屏和电源事件 |
| 界面 | React + TypeScript + Vite | 宠物、气泡、工具卡片和小窝 |
| 本地界面状态 | Zustand | 窗口展开、当前动画等瞬时状态 |
| 接口校验 | Zod | IPC、工具参数、模型结构化结果和配置校验 |
| 持久化 | SQLite + better-sqlite3 | 本地事务、检索、提醒、记忆与事件记录 |
| 时间 | UTC 毫秒时间戳 + IANA 时区；Temporal polyfill 处理换算 | 时区、日期解析、恢复与夏令时边界 |
| 模型 | 一个支持流式对话与工具调用的服务适配器 | 云端服务或兼容协议的本地服务 |
| 测试 | Vitest；桌面集成可使用 Playwright Electron 支持 | 决策规则、持久化、工具与关键窗口流程 |
| 打包 | electron-builder | Windows 安装包与解压版 |
| 包管理 | pnpm workspace | 统一前后端类型与开发命令 |

首版使用一个 Electron 应用，不额外部署 Python、Web 后端、向量数据库或任务队列。模型请求在主进程的服务层发起；动画与高频指针反馈不等待模型。

`better-sqlite3` 涉及 Electron 原生模块 ABI。搭建工程时应验证安装、重建和打包后的数据库读写，再继续开发功能。版本写入锁文件，不在本文硬编码未经验证的版本号。

## 4. 进程与模块结构

```text
渲染进程
  PetStage       宠物、动画与拖动反馈
  Bubble/Card    气泡、操作卡片、对话
  HomePanel      小窝、工具、记忆与设置
       │
       │ preload 暴露的有类型窄接口
       ▼
Electron 主进程
  WindowManager / Tray / Lifecycle
  CommandService ── ToolRegistry ── Repository ── SQLite
  EventBus ── ProactivePolicy ── PresentationQueue
  ConversationService ── ModelAdapter
  MemoryService / PersonalityService / Scheduler
```

职责约定：

- 主进程是持久数据与业务规则的唯一写入口。
- 渲染进程负责展示和输入，不直接访问 SQLite、文件系统、密钥或模型服务。
- Zustand 保存界面状态；数据库保存任务、偏好、记忆、提醒和对话。避免两份独立的业务真相。
- 模型服务提供文本、候选意图与候选记忆；规则层决定能否执行和保存。
- EventBus 是进程内事件分发；需要跨重启恢复的事件写入数据库。
- 高频动画留在渲染进程。长时间 CPU 工作出现后再迁入 worker/utility process。

## 5. 桌面窗口与输入

### 5.1 窗口划分

- PetWindow：透明、无边框、可调整置顶策略的宠物窗口；平时不抢键盘焦点。
- PanelWindow：按需打开的气泡、对话或工具卡片；用户主动输入时才获得焦点。
- HomeWindow：普通交互面板，承载小窝、详细记录和设置。
- 所有附属窗口跟随宠物重新计算位置，越界时翻转或收回屏幕可用区。
- 托盘提供显示/隐藏、打开小窝、安静模式和真正退出。关闭面板不等于退出应用。

### 5.2 透明区域与拖动

- 透明背景不自动等于鼠标穿透；必须实现可交互区域命中检测。
- 可以先评估 `setIgnoreMouseEvents` 配合鼠标转发与角色区域判断的实现；Windows 下须验证是否会吞掉底层点击，以及触碰、拖动、文字拖入的切换。
- 无法可靠命中时，可使用小型明确交互区或窗口区域方案，但不能用覆盖整个屏幕的透明窗口拦截输入。
- 按下后超过约 5 DIP 的移动距离才认定拖动，避免点击被误判。
- 进入拖动后保持输入捕获，结束后再恢复穿透判断。拖动过程只更新显示，结束时保存位置。
- 首版落地采用确定性的短动画和缓动；边缘吸附不要求真实物理模拟。
- 文字拖入先检查类型与长度；文件拖入给出明确的当前能力提示。

### 5.3 多屏与 DPI

- 统一使用 Electron 窗口坐标所需的 DIP；来自其他来源的物理像素坐标先转换，不混用。
- 保存显示器标识、相对可用区位置与角色缩放。
- 显示器拔出或工作区变化后，将宠物移入现有显示器的可用区域。
- 覆盖 100%/125%/150% 缩放、不同缩放双屏、负坐标显示器和任务栏位置变化。
- 全屏、锁屏期间暂停普通主动展示；到期事项保留在队列或信箱，恢复时按优先级合并展示。

## 6. 动画、性格与状态

将状态分开建模，避免所有行为挤进一个大型枚举：

| 维度 | 示例 | 更新依据 |
| --- | --- | --- |
| 身体状态 | idle / walk / lifted / landing / sleep | 输入、动画完成、时间 |
| 工作状态 | none / thinking / executing / waiting / success / error | 真实工具与对话事件 |
| 表达状态 | calm / curious / happy / sleepy | 角色性格、事件、昼夜节奏 |
| 互动模式 | normal / quiet / focus / hidden | 用户设置与生命周期 |

仲裁顺序建议：拖动等直接操控 > 必须反馈的执行状态 > 用户触碰 > 自主动作 > 待机。

- 性格基线写入角色配置：温和、好奇、略笨拙；用户可调整表达风格。
- 短期表达状态有强度、来源和到期时间，变化平滑；恢复应用后不积累“被冷落”的负面情绪。
- 完成任务可以开心，失败可以困惑；禁止用开心动画或台词掩盖失败。
- 情绪不必每次调用模型；多数状态由本地事件映射决定。
- 模型返回的表达标签必须经过白名单映射，并允许回退到 calm。

角色素材 manifest 至少定义：角色 ID、名称、版本、帧图集、动作帧率、循环标记、锚点、命中区域、缺失动作回退和素材许可。

动作系统接受语义命令，例如 `play("lifted")`、`showWorkState("executing")`；业务代码不直接引用某张图片。没有最终美术时使用原创占位形状与简易动画。

## 7. 工具系统与执行约定

工具使用统一注册表，每个工具定义：名称、用途、输入 schema、输出 schema、执行函数、可取消性、幂等策略和权限级别。

首版工具：

```text
notes.create / list / search / update / delete
tasks.create / list / update / complete
reminders.create / list / reschedule / cancel
focus.start / pause / resume / cancel / finish
preferences.set / list
memories.list / correct / forget
keepsakes.create / list / delete
```

执行流程：

```text
用户输入或操作
  → 意图解析
  → Zod 参数校验 + 时间/目标校验
  → 规则判断与必要的消歧
  → 工具执行 + 数据库事务
  → 结构化结果 + 业务事件
  → 结果卡片 + 动作 + 可选自然语言回应
```

约定：

- 明确提出的创建提醒、记录、待办等本地动作直接执行，不重复确认。
- 缺少关键时间、存在多个同名目标、或“下午”没有具体时刻时，询问最小必要信息；不得伪装为已设置。
- 使用 `requestId`/幂等键阻止重复点击、IPC 重试或工具调用重放造成重复创建。
- 明确的删除操作可执行，普通记录先软删除并提供短期撤销；模型不能擅自发起批量删除。
- 首版工具注册表不包含付款、外发消息、任意 shell 或电脑自动控制。
- UI 直接操作与模型工具调用走同一服务层，保证规则一致。
- 返回至少包含 `ok`、`requestId`、`result` 或 `errorCode`；模型只能解释真实结果。

## 8. 数据模型与持久化

数据目录使用 `app.getPath("userData")`，不要存放到安装目录或源码目录。SQLite 启用外键；根据验证结果启用 WAL。数据库迁移编号管理，不使用静默删库重建。

所有时间以 UTC 毫秒保存；展示和用户语义解析保留 IANA 时区。首次默认使用系统时区，不固定为开发者所在时区。

建议核心表：

| 表 | 关键字段与用途 |
| --- | --- |
| settings | key、valueJson、schemaVersion、updatedAt；全局设置 |
| preferences | key、valueJson、source、sourceEventId、updatedAt；已生效的用户偏好 |
| pet_state | petId、displayId、relativeX/Y、scale、personaVersion；角色与桌面位置 |
| notes | id、title、body、createdAt、updatedAt、deletedAt |
| tasks | id、title、status、dueAt、progressNote、completedAt、deletedAt |
| reminders | id、taskId?、content、dueAt、timeZone、status、revision |
| reminder_occurrences | id、reminderId、revision、scheduledAt、createdAt；一次到期事件 |
| focus_sessions | id、taskId?、status、durationMs、startedAt、dueAt、remainingMs、endedAt |
| conversation_messages | id、conversationId、role、content、toolCallId?、createdAt |
| memories | id、kind、content、sourceType、sourceId、confidence、status、expiresAt、updatedAt |
| keepsakes | id、title、description、memoryId?、decorationId?、createdAt、deletedAt |
| events | id、type、source、payloadJson、occurredAt、correlationId |
| outbox | id、eventId、category、priority、dedupeKey、status、availableAt、expiresAt |
| interaction_feedback | id、candidateId、feedbackType、scope、createdAt；主动行为反馈 |

索引与约束：

- `reminder_occurrences(reminderId, revision)` 唯一，防止同一次计划重复创建到期记录。
- `outbox(dedupeKey)` 唯一，同一事项只有一张逻辑卡片。
- 通过约束或事务保证最多一个 running/paused 专注会话。
- reminders 的状态与 dueAt、tasks 的状态、memories 的状态与 kind、outbox 的状态与 availableAt 建立索引。
- 随手记首版可使用 SQLite FTS5 搜索；工程初始化验证打包版本支持。中文可先实现规范化子串匹配，避免宣称具备未经验证的中文分词能力。
- 重要修改产生业务事件，但不把密钥、完整原始模型请求和不必要的敏感内容复制进事件日志。

## 9. 提醒与专注恢复

### 9.1 提醒

- 数据库记录是提醒真相来源；内存定时器仅负责唤醒检查。
- 创建和修改时持久化内容、绝对时间、时区与 revision；修改后使旧计划失效。
- 启动、恢复、系统时间变化和短周期检查时，重新查询到期提醒；不能只依赖长时间 `setTimeout`。
- 到期时，在同一事务中校验 revision、创建 occurrence 和 outbox 项，再推进提醒状态。
- 取消、改期与到期触发必须重新读取最新记录，避免旧提醒在取消后弹出。
- 未展示事项进入信箱；用户忽略气泡不等于完成关联任务。
- 退出期间错过的提醒在下次启动汇总。初始建议：24 小时内的近期事项给一次汇总提示，更早事项仅放入信箱；此阈值可配置。
- 主动闲聊配额不限制用户自己设置的提醒，但同一时间多个到期提醒应合并展示。
- 隐藏或安静模式下保留提醒卡片；是否使用系统通知由独立设置决定。
- 应用真正退出时不承诺实时提醒。首版依靠后台运行和可选开机启动；若需要关闭后仍准时通知，须另行设计系统级调度。

事件处理按“可重试 + 幂等写入”设计。跨崩溃的 UI 展示不能轻率承诺严格 exactly-once；应确保逻辑提醒不重复，并通过稳定 ID 降低重复气泡。

### 9.2 专注

- 支持开始、暂停、继续、取消和完成；可选关联待办。
- 运行中保存截止时间，暂停时保存剩余时长，界面倒计时由时间差计算。
- 默认按自然经过时间计时，睡眠和锁屏仍计时；结束展示延迟到可交互时刻。
- 启动后恢复会话，已到期的会话只结算一次。
- 到时不自动宣称任务完成；由用户确认完成、记录进展或继续。
- 单次运行中可用单调时钟帮助检测系统时钟跳变；跳变后重新校准，避免负数和重复结算。

## 10. 对话与模型适配

定义稳定的 `ModelAdapter`，首版只实现一个服务，不为每家厂商复制业务逻辑：

```ts
interface ModelAdapter {
  stream(request: ModelRequest, signal: AbortSignal): AsyncIterable<ModelChunk>;
}
```

请求上下文按以下顺序组装：

1. 角色基线和真实能力边界。
2. 用户显式偏好与当前互动模式。
3. 当前时间、时区、正在处理的事项和真实工具结果。
4. 与本次请求相关的有效记忆。
5. 有限的近期对话与用户输入。

实现要求：

- 对上下文设长度预算，相关记忆优先；不把全部历史反复发送。
- 保留“先有上下文、再有工具执行、再解释结果”的顺序。
- 流式回复可停止；停止生成与取消工具分别处理，不能把已提交的写入假装撤销。
- 设置请求超时、有限重试和工具调用轮次上限；重试写工具仍须使用原幂等键。
- 同一对话的写操作串行化；普通闲聊不得阻塞到期提醒。
- 模型返回格式错误时回退到短提示或参数补全，不执行未经校验的动作。
- 网络不可用时保留输入，展示可重试状态；本地工具卡片继续工作。
- API 地址、模型名与密钥通过设置配置。兼容协议的本地模型可以使用同一适配器，但不承诺所有服务实现完全兼容。

## 11. 记忆与个性化

### 11.1 记忆分类

- 相处偏好：称呼、语气、主动程度、安静时段、明确兴趣。
- 近期事项：目标、进度、未完成话题和已约定的跟进。
- 共同回忆：用户确认值得留下的成果、事件和话语。
- 临时上下文：今天疲惫、当前忙碌等有时效的信息。

### 11.2 保存与纠正

- “这个记住”“工作日上午少聊天”等明确指令可直接生效，并返回可编辑结果。
- 模型提取的偏好先成为 pending 候选，不直接覆盖显式偏好。
- 一次忽略只影响当前候选和短期主动频率，不直接写入永久人格判断。
- 共同回忆由用户创建或接受提议后保存；普通任务完成事件不自动变成纪念物。
- 事实记忆绑定来源记录，推测记录标注来源与置信度。置信度是系统字段，不包装成科学测得的情绪概率。
- 临时状态有 expiresAt；近期事项在任务结束后归档或失效。
- 用户纠正后，旧记忆标为 superseded；检索不得再次注入旧结论。
- 用户删除记忆后，同时清理相关检索索引和关联缓存。历史对话仍可能包含原话，应在界面说明并允许单独删除相关对话。
- 允许查看、修改、忘记和导出；更换角色皮肤继续使用同一用户数据。

### 11.3 检索

首版使用结构化键、实体/任务关联、关键词与时间范围检索。优先级：有效显式偏好 > 当前事项 > 相关已确认回忆 > 其他近期上下文。

先完成记忆准确性、失效与纠正，再评估向量检索。禁止为了“更懂用户”而无界保存所有推测。

## 12. 自主行为机制

### 12.1 事件驱动

事件示例：

```text
app.started / app.resumed / app.locked / app.unlocked
user.message_received / user.pet_touched / user.text_dropped
task.created / task.completed / task.progress_updated
reminder.due / focus.started / focus.finished
preference.changed / memory.corrected
proactive.accepted / proactive.postponed / proactive.dismissed
```

业务事件包含稳定 ID、来源、发生时间和关联对象。系统生成的主动触发不能伪装为用户发出的真实消息写入历史。

### 12.2 候选与筛选

主动候选至少包含：原因、证据引用、类别、有效时间窗、优先级、去重键、建议展示方式和是否需要生成文本。

```text
事件或轻量调度
  → 生成候选
  → 校验依据和有效期
  → 检查锁屏、专注、安静时段、隐藏状态
  → 检查配额、冷却、重复和近期反馈
  → 选择一个候选
  → 必要时调用模型生成短表达
  → 卡片/动作/信箱
  → 保存反馈并调整行为
```

只有通过本地筛选的候选才调用模型，不让每次定时检查都请求模型。

### 12.3 初始默认策略

- 非必要主动互动：每天最多 2 次，按用户本地日期统计。
- 非必要主动互动冷却：至少 60 分钟。
- 明确预约的提醒与跟进单独调度，不占闲聊配额。
- 专注、锁屏期间抑制普通闲聊；解锁后重新判断，过期候选丢弃。
- 默认一次只展示一个主动气泡；任务提醒高于兴趣分享，兴趣分享高于玩耍邀请。
- 没有回应时自然收起，不连续追问、不制造内疚。
- “稍后”只调整这次；“这类少一点”调整类别权重；“工作时安静”保存时间规则。
- 候选一旦展示，记录展示时间和配额；不能因程序重启重新获得整天配额。

以上是可调起点，不是已经验证的最优参数。保留理由记录，便于分析“为什么出现”和“为什么被抑制”。

## 13. 小窝与共同空间

首版使用轻量二维面板，避免先建设复杂游戏场景：

| 入口 | 功能 |
| --- | --- |
| 小本子 | 随手记、待办、搜索 |
| 沙漏 | 专注会话、当前进度 |
| 信箱 | 到期提醒、跟进卡片、待看内容 |
| 相册 | 共同回忆、来源和编辑 |
| 小箱子 | 皮肤、收藏摆件、外观设置 |
| 相处设置 | 偏好、主动程度、安静时段、已保存记忆 |

- 小窝中的任务和宠物卡片使用同一份数据库记录。
- 回忆可以关联一个预置原创摆件；删除回忆时允许选择是否保留装饰。
- 摆件是纪念入口，不提供签到断签惩罚或必须完成任务才能维持的生命值。
- 信箱是持久记录，气泡是一次展示；二者生命周期分开管理。
- 动画、颜色之外保留可读文字；支持关闭声音、降低动态效果和调整尺寸。

## 14. IPC、密钥与数据边界

- BrowserWindow 使用 `contextIsolation: true`、`nodeIntegration: false`，尽量保持 sandbox 开启。
- preload 只暴露明确的命令与订阅，例如 `notes.create`、`reminders.reschedule`、`pet.move`；不提供任意 SQL、shell、文件路径读取或通用任意频道发送。
- 对每个 IPC 校验发送窗口、参数、长度和业务权限；事件订阅在组件卸载时清理。
- 仅加载受控的本地界面，设置 CSP；外部链接通过明确入口交给系统浏览器。
- 密钥在主进程通过 Electron safeStorage 等系统能力加密后保存，不放在渲染状态、日志或普通导出文件中。
- 数据库不因此自动具备全库加密；若需要完整静态加密，作为独立需求设计。
- 用户拖入的文本、笔记与模型内容都是数据，不允许它们越过工具注册表变成任意指令。
- 首版数据保存在本机，但使用云模型时相关输入会发送给所配置服务；设置中明确展示这一点。
- 提供数据导出与清理入口；导出不包含 API 密钥。

## 16. 验证与验收

对有持久状态、时间、模型边界和决策规则的部分写有意义的测试。简单布局和文案不需要机械地增加测试。

重点自动化验证：

- 时间解析：跨日、时区、夏令时歧义、系统时钟变化和已过去时间。
- 提醒：创建后重启、改期后旧计划失效、取消和到期竞争、睡眠恢复、同一事件重放不重复创建。
- 专注：暂停继续、重启恢复、到期只结算一次、计时结束不自动完成任务。
- 工具：参数缺失不写入、失败不报告成功、相同请求重试不重复创建。
- 记忆：显式偏好优先、临时状态过期、纠正后旧记忆不被检索、删除与导出一致。
- 自主性：安静时段、跨午夜配额、冷却、忽略反馈、候选过期、重启后配额保持。
- 模型：超时、中断、错误 JSON、无效工具、重复工具调用与有限重试。
- 数据：迁移失败不破坏旧库、基础导出恢复、IPC 拒绝非法参数。

Windows 人工验收：

- 透明区域不拦截底层点击；摸头、拖动、文字拖入互不冲突。
- 100%/125%/150% 缩放与混合 DPI 双屏下位置正确。
- 托盘、隐藏、置顶、锁屏、全屏、睡眠和显示器拔出行为符合设计。
- 配置模型前后都可使用基础桌宠与工具。
- 后台空闲没有持续模型请求、无无界日志或逐帧数据库写入。
- 试验目标：普通 Windows 笔记本静置时平均 CPU 低于约 2%，内存争取低于约 300 MB；作为待测预算，实际报告注明机器与素材条件。

一周核心场景：

1. 用户认识宠物，设置称呼、表达方式和主动程度。
2. 用户说“明天下午三点提醒我改简历”，应用展示准确的本地日期时间并保存。
3. 退出重启后记录仍在；到期展示，推迟后原计划不再重复触发。
4. 用户开始专注，宠物安静陪伴，结束后询问进展。
5. 用户说“工作日上午少聊天”，之后同类主动行为受到抑制。
6. 用户确认保存一段共同回忆，在相册和小窝中可找到并可删除。
7. 一周后继续简历话题，应用能使用真实进度；模型离线时仍能查看和修改这些记录。
